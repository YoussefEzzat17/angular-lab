Route Guards

A guard is a function the router runs before opening a page. It decides whether the user may enter, and where to send them if not. This guide covers canActivate, canActivateChild, canDeactivate, canMatch and resolve, how to redirect correctly, and how to test a guard.

1 · WHY GUARDS EXIST

Routing says which page; a guard says whether

Without a guard, anyone who types /admin into the address bar gets the admin page. A route guard is a small function the router calls before it activates a route. Its answer decides what happens next.

User clicks a link→Router finds the route→Guard runs→Page opens

If the guard says no, the router can cancel the navigation (the user stays where they were) or redirect to another URL such as a login page.

Typical useGuard question
Login requiredIs the user signed in?
Roles / permissionsMay this user see the admin area?
Unsaved changesReally leave this form with unsaved edits?
Feature flagsDoes this route even exist for this user?
Data firstLoad what the page needs before it shows (resolver)
ImportantA guard only controls what the browser shows. Anyone can change client-side code, so never treat a guard as real security. The server must check the token on every API call.
2 · THE GUARD IN ONE FUNCTION

canActivate: return true, false, or a UrlTree

Modern Angular guards are plain functions (CanActivateFn). They run inside an injection context, so inject() works for services and the router.

export const membersGuard: CanActivateFn = () => {
  const auth = inject(AuthService);
  const router = inject(Router);

  return auth.loggedIn()
    ? true                                   // let the user in
    : router.createUrlTree(['/login'], {      // redirect instead
        queryParams: { returnUrl: '/members' },
      });
};

// app.routes.ts
{ path: 'members', canActivate: [membersGuard], loadComponent: () => import('./members') }
Return valueWhat the router does
trueContinues: the page opens.
falseCancels the navigation. The user stays put (and sees nothing happen).
UrlTreeCancels this navigation and redirects to that URL as part of the same navigation.
Observable / PromiseAny of the above, delivered later (e.g. after an HTTP check). An Observable must emit and complete (use take(1) or first()).
3 · REDIRECT THE RIGHT WAY

Return a UrlTree — don't call router.navigate() inside the guard

Calling router.navigate() from a guard starts a second navigation while the first is still in progress. Returning a UrlTree lets the router cancel the first one and redirect as one clean step, so history and the back button behave.

Avoid

if (!auth.loggedIn()) {
  router.navigate(['/login']);
  return false;
}
return true;

Prefer

return auth.loggedIn()
  ? true
  : router.createUrlTree(['/login']);
TipAngular 18.2+ also has RedirectCommand (new RedirectCommand(urlTree, { skipLocationChange: true })) when you need extra navigation options on the redirect.
4 · THE FIVE KINDS

Pick the guard that matches your question

GuardQuestion it answersTypical code
canActivateMay the user open this route?login / role check
canActivateChildSame, for every child under a parent routeone guard on an /admin parent
canDeactivateMay the user leave this page?unsaved-changes prompt
canMatchShould this route match at all? A failing route is skipped and the router tries the next one; it also stops a lazy chunk from being downloaded.role-based routes, feature flags
resolveNot a yes/no: fetch the data the page needs before it shows.load a product by id

canLoad still exists but is deprecated — use canMatch.

5 · MORE EXAMPLES

canDeactivate, canMatch and resolve

// canDeactivate: ask before leaving a dirty form
export interface HasUnsavedChanges { hasChanges(): boolean }
export const leaveGuard: CanDeactivateFn<HasUnsavedChanges> = (page) =>
  !page.hasChanges() || confirm('Discard your changes?');

// canMatch: this route only exists for admins (and its chunk is never downloaded otherwise)
export const adminMatch: CanMatchFn = () => inject(AuthService).isAdmin();
{ path: 'admin', canMatch: [adminMatch], loadChildren: () => import('./admin/routes') }

// resolve: load data before the page appears
export const productResolver: ResolveFn<Product> = (route) =>
  inject(ProductService).getById(Number(route.paramMap.get('id')));
{ path: 'products/:id', resolve: { product: productResolver }, component: ProductPage }
6 · ORDER OF EVENTS

What happens during a navigation

canMatch runs while the router works out which route matches.
canDeactivate runs on the page being left.
canActivateChild (parent → child), then canActivate run on the page being opened.
resolve loads the data the page needs.
The route activates and the component is created.

Several guards in one array must all allow the navigation. If one returns a UrlTree, that redirect is used instead.

7 · TESTING A GUARD

It is just a function — run it in an injection context

it('redirects to /login while logged out', () => {
  TestBed.configureTestingModule({ providers: [provideRouter([])] });

  const result = TestBed.runInInjectionContext(() => membersGuard({} as any, {} as any));

  expect(result instanceof UrlTree).toBeTrue();
  expect(TestBed.inject(Router).serializeUrl(result as UrlTree)).toBe('/login');
});

Replace AuthService with a fake in providers to test both the allowed and the blocked path without any real login.

8 · COMMON MISTAKES

Things that trip people up

  • Trusting the guard for security. It only hides pages in the browser. Always verify on the server.
  • Calling router.navigate() in the guard. Return a UrlTree instead.
  • An Observable that never completes. The navigation waits forever. Add take(1).
  • Redirect loops. A guard that redirects to a route guarded by itself. Send users to a public page (e.g. /login).
  • Using a class-based guard. CanActivate classes are deprecated; use functional guards.
  • Forgetting canMatch for lazy loadChildren routes. canActivate runs after those child routes were already downloaded; canMatch runs first and prevents the download.
